# 多模态输入与参考素材指南

Seedance 2.0 的核心优势是多模态输入——同时传入文本、图片、视频、音频，模型自动整合生成视频。正确使用参考素材比只写提示词效果稳定得多。

## 参考素材类型与上限

| 素材类型 | Content type | Role 值 | 数量上限 | 格式 | 大小限制 |
|---|---|---|---|---|---|
| 文本 | `text` | — | 1 个（必须有） | — | — |
| 图片 | `image_url` | `first_frame` / `last_frame` / `reference_image` | 0–9 张 | PNG/JPG/JPEG/WebP/GIF/BMP/TIFF/HEIC/HEIF | < 30 MB |
| 视频 | `video_url` | `reference_video` | 0–3 段 | **仅 MP4 / MOV**（H.264 或 H.265/HEVC + 容器内 AAC/MP3，24-60 fps） | < **200 MB** |
| 音频 | `audio_url` | `reference_audio` | 0–3 段 | **仅 WAV / MP3**（官方明文支持，其它格式请先转码） | < 15 MB，单段 [2, 15]s |

**单类型上限：图 9 / 视 3 / 音 3**。官方未明文规定总数硬上限，但**脚本 client 侧硬限总计 ≤ 12**（防呆）；**实测推荐 4-5 个素材的黄金配比**（见 [key-constraints.md](key-constraints.md)），过多素材会导致特征优先级混乱、风格冲突、主体识别模糊。

> **注意**：上面是**输入参考素材**的体积限制，**不是输出 video 的体积限制**。整个请求体 base64 编码后 ≤ 64 MB，脚本 client 侧 hard-fail 在 60 MB（留 4MB 余量）。详细见 [key-constraints.md](key-constraints.md) 的「输入参考素材 size 限制」一节。

## 传输方式（URL / base64 / asset://）

| 素材类型 | http(s):// URL | base64 data URL | `asset://` 素材 ID |
|---|---|---|---|
| 图片（含 first_frame / last_frame）| ✅ | ✅ 本地图片脚本自动转 | ✅ |
| 视频 | ✅ | ❌ **不支持**，视频必须走 URL 或 asset:// | ✅ |
| 音频 | ✅ | ✅ 本地 WAV/MP3 脚本自动转 | ✅ |

> **关键区别**：图片和音频支持 base64，脚本会自动把本地文件转成 data URL；**视频不支持 base64**，本地视频必须先上传到公网 bucket（TOS/S3）或录入素材库用 asset:// 引用。脚本会在 client 侧直接拦截本地视频路径并给出错误提示。

## API 中如何传入

### content 数组结构

```json
{
  "content": [
    {"type": "text", "text": "提示词..."},
    {"type": "image_url", "image_url": {"url": "https://..."}, "role": "reference_image"},
    {"type": "video_url", "video_url": {"url": "https://..."}, "role": "reference_video"},
    {"type": "audio_url", "audio_url": {"url": "data:audio/mpeg;base64,..."}, "role": "reference_audio"}
  ]
}
```

支持的 url 形式：
- `https://example.com/image.png` — 公网 URL
- `data:image/png;base64,iVBOR...` — base64 data URL（仅图片/音频）
- `asset://<asset-id>` — 火山素材库 ID（图片/视频/音频都支持）

### 提示词中如何引用

提示词中必须用 `图片n`/`视频n`/`音频n` 格式（n 为**同类型素材在 content 数组中的排序**，从 1 开始；不是所有素材的全局排序），**不支持 Asset ID 直接指代**。

```
参考图片1中的角色面部，参考视频1中的运镜方式，使用音频1作为背景音乐
```

> 若首帧是 `图片1`，后面有 2 张参考图，则参考图分别是 `图片2`、`图片3`。模型按「同类型序号」定位素材。

## 四种功能角色

按功能分工组织素材，每种 1-2 个即可，**不要用满上限**：

| 功能角色 | 素材类型 | 作用 | 推荐数量 |
|---|---|---|---|
| 角色锚定 | 图片 | 锁定角色五官/服装/体型 | 1-2 张（大头照 + 全身照）|
| 场景定调 | 图片 | 锁定环境、光源、色调、美术风格 | 1 张 |
| 运镜参考 | 视频 | 锁定镜头语言、动作节奏、构图方式 | 1 段 |
| 氛围音频 | 音频 | 控制情绪基调、背景音类型、旁白音色 | 1 段 |

**黄金配比：4-5 个素材**。过多会导致特征优先级混乱、风格冲突、主体识别模糊。

## 各参考类型详解

### 图片参考（reference_image）

适用场景最广，角色/场景/风格/构图/Logo/道具都可以用图片传。

| 参考类型 | 说明 | 提示词示例 |
|---|---|---|
| 主体多视角 | 同一个角色的面部 + 全身 + 侧面（仅限人物）| `参考图片1的面部、图片2的全身，生成她走路的场景` |
| 场景参考 | 锁定背景、光影、时间 | `参考图片3的场景风格，将人物放置在类似环境中` |
| Logo 参考 | 在画面固定位置展示品牌标识 | `画面右下角始终显示图片5中的标识` |
| 商品 3C | 多角度产品图 | `提取图片1、图片2、图片3中的相机，以相机为主体缓慢旋转` |
| 多宫格分镜图 | 四格/九格漫画式参考 | `参考图片中的分镜图，按照顺序生成相应镜头` |
| 多元素参考 | 角色 + 服装 + 场景 + Logo 组合 | `场景设定在图片4的餐厅内，图片1的女孩身着图片2的服装，图片5的标识始终显示在右下角` |
| 风格/样张参考 | 锁定美术风格和色调 | `参考图片1的赛博朋克风格，生成都市夜景` |

> **多视角参考仅适用于人物主体**。物体/商品/建筑不建议用多视角拼接，会导致模型混淆结构。

### 视频参考（reference_video）

| 参考类型 | 说明 | 提示词示例 |
|---|---|---|
| 动作参考 | 提取视频中人物的运动方式和节奏 | `参考视频1的人物动作，生成张三在同样节奏下出拳` |
| 运镜参考 | 提取视频中的镜头运动和构图 | `参考视频1的运镜，做成科技园区的概念视频` |
| 特效参考 | 提取粒子效果、光效等的形态和运动逻辑 | `参考视频1的金色粒子特效，让角色身边环绕一样的特效` |
| 风格/氛围参考 | 提取色调、镜头感、画面调性 | `全程使用视频1的第一视角构图和有质感的画面风格` |

**视频参考技术要求**：
- 容器：**仅 MP4（.mp4, video/mp4）和 QuickTime（.mov, video/quicktime）**；AVI/MKV/WebM 等不接受
- 视频编码：H.264/AVC 兼容性最佳；H.265/HEVC 也支持
- 容器内音频：AAC 或 MP3
- FPS：∈ [24, 60]
- 分辨率：480p ~ 4k；总像素 ∈ [409600, 8295044]；单边 ∈ [300, 6000] px；宽高比 ∈ (0.4, 2.5)
- 文件大小：≤ 200 MB
- 不要用经过多次剪辑/压缩/转发的视频，元数据破坏会影响特征提取

### 音频参考（reference_audio）

| 参考类型 | 说明 | 提示词示例 |
|---|---|---|
| 背景音乐 | 情绪、节奏、配器风格 | `全程使用音频1作为背景音乐` |
| 音色参考 | 旁白/角色的声线、音色特征（在提示词中补细致描述防漂移）| `使用@音频1低厚温润带细碎颗粒感中年男声的音色` |
| 环境音效 | 提取音频中的环境声氛围 | `环境音效与音频1自然融合` |

> 本地 WAV/MP3 脚本会自动转 base64 上传；**官方仅明文支持 wav 和 mp3**，其它格式（AAC/FLAC/M4A/OGG）请先转码再传，否则可能被 400 拒绝。

## 模式组合规则

**唯一硬互斥**：`first_frame`/`last_frame` 与 `reference_image` 不能在同一次请求中同时出现。

| 模式 | 使用的 role | 是否允许组合 |
|---|---|---|
| 首帧/首尾帧 | `first_frame`（+ `last_frame`） | 与 `reference_image` ❌ 互斥；与 `reference_video`/`reference_audio` ⚠️ 共存未在官方文档明文确认 |
| 多模态参考 | `reference_image` + `reference_video` + `reference_audio` | ✅ 三类自由组合 |
| 纯文生视频 | 只有 `text` | ✅ 可加 `enable_web_search` |
| 视频编辑/延长 | `reference_video`（作被编辑对象） | ✅ 可与 `reference_image`、`reference_audio` 组合 |

**首尾帧 + 视频/音频参考的推荐做法**：官方文档把首尾帧模式和多模态参考模式定位为两条独立路径，**没有明文支持** `first_frame`/`last_frame` 与 `reference_video`/`reference_audio` 共存。

- 优先方案：用**多模态参考**模式，把目标图作为 `reference_image` 传入并在 prompt 中描述「以图片N为首帧/尾帧」。
- 如果必须像素级一致地控制首尾帧：单独走首尾帧模式，先不带视频/音频参考；视频/音频特征通过 prompt 文本描述。
- 如确实想同次混用 `first_frame` + `reference_video`/`reference_audio`：先用 `--dry-run` 看 payload，再 submit 一个最小测试 task 验证 API 是否接受。

**首尾帧画面比例处理**：首帧和尾帧宽高比不一致时，**以首帧为准**，尾帧会被自动中心裁剪以适配；首尾帧图片**允许相同**（用于「回到原点」式叙事）。输出 ratio 与输入图比例不一致时，服务端按中心裁剪；建议预裁或设 `ratio=adaptive`。

**注意**：多模态参考模式中，可以通过提示词指定参考图片作为首帧/尾帧，间接实现"首尾帧 + 参考"效果。但如果需要严格保障首尾帧与指定图片像素级一致，优先使用首帧/首尾帧模式。

## 视频编辑与延长

### 编辑视频

在原视频基础上修改，`reference_video` 角色的素材就是待编辑的视频：

| 操作 | 提示词示例 |
|---|---|
| 增加元素 | `在视频1的台面上添加炸鸡、披萨等小吃` |
| 删除元素 | `清除视频1桌面上的零件和工具，保持桌面整洁` |
| 修改/替换 | `将视频1中的香水替换成图片1中的面霜，运镜不变` |
| 局部重绘/修复 | `将视频1中的墙壁重新粉刷成白色，保持其他元素不变` |
| 天气/光线替换 | `将视频1中的晴天改为雨夜，霓虹灯反射在湿漉漉的地面上` |

### 延长视频

在时间维度上延伸视频，最多 3 段视频串联，总时长 ≤ 15 秒：

| 操作 | 提示词示例 |
|---|---|
| 向后延长 | `生成视频1之后的内容，角色继续说{这段台词}` |
| 向前延长 | `向前延长视频1，给角色一个过肩镜头，他说：{这句台词}` |
| 轨道补齐 | `视频1 + 树叶落地金色粒子特效 + 接视频2` |

> **延长衔接处跳变的处理**：前段删 6 帧 + 后段删 1 帧，以转场切镜结尾，避免硬切跳变。延长后画质劣化时，可先产出白模视频再续写，避免多次续写。

## 虚拟人像与授权素材（asset:// 协议）

Seedance 2.0 系列**不支持上传任何真人人脸的参考图/视频**（不限公众人物）。平台提供三种合规方案：

| 方案 | 用法 | 收费 |
|---|---|---|
| 预置虚拟人像库 | `image_url.url: "asset://<asset-id>"`，图片/视频/音频都支持 asset:// | 免费 |
| 已授权真人素材 | 录素材入库后使用 asset:// 协议 | 免费 |
| Seedream 5.0 lite 生成人脸 | 同账号 30 天内信任产物，可作 reference_image | 按 Seedream 计费 |

**注意**：Asset ID 仅用于 content 中的 url 字段，提示词中仍需用 `图片n`/`视频n`/`音频n` 引用。

## 本地文件处理

| 文件类型 | 支持方式 |
|---|---|
| 本地图片（PNG/JPG/JPEG/WebP/GIF/BMP/TIFF/HEIC/HEIF） | ✅ 脚本自动转 base64 data URL |
| 本地 WAV/MP3 音频 | ✅ 脚本自动转 base64 data URL |
| 本地视频（仅 MP4/MOV 接受；其他容器请先转码） | ❌ 需先上传到可公开访问的 URL 或 TOS，或录入 asset:// 素材库 |
| 本地其他音频格式（AAC/FLAC/M4A/OGG 等） | ⚠️ 官方仅明文支持 WAV/MP3，建议先转码再传，否则可能被 400 拒绝 |

## 参考素材最佳实践

1. **素材越重要，提示词中越靠前**。越精准参考的素材，放在提示词越靠前的位置。
2. **人脸参考用大头照 + 全身照，不用三视图**。三视图易导致人物重复或 ID 漂移（双胞胎 bug）。
3. **参考人物 ≤ 4 人**。超过 4 人需分组建模。
4. **多视角参考仅用于人物**。物体/商品/建筑不要用多视角拼接。
5. **不要用多次剪辑/压缩/转发的视频做参考**。元数据破坏会导致特征提取失败。
6. **参考素材先去除文字/水印**。图里带文字会被模型误识别为要生成字幕。
7. **视频 URL 24 小时过期**。长期保存建议转存到火山引擎 TOS 或配置 TOS 数据订阅自动转存。
