# 多模态输入与参考素材指南

Seedance 2.0 的核心优势是多模态输入——同时传入文本、图片、视频、音频，模型自动整合生成视频。正确使用参考素材比只写提示词效果稳定得多。

## 参考素材类型与上限

| 素材类型 | Content type | Role 值 | 数量上限 | 格式 | 大小限制 |
|---|---|---|---|---|---|
| 文本 | `text` | — | 1 个（必须有） | — | — |
| 图片 | `image_url` | `first_frame` / `last_frame` / `reference_image` | 0–9 张 | PNG/JPG/WebP | < 30 MB |
| 视频 | `video_url` | `reference_video` | 0–3 段 | MP4/MOV | < 50 MB |
| 音频 | `audio_url` | `reference_audio` | 0–3 段 | MP3/WAV | < 15 MB，单段 [2, 15]s |

**总计不超过 12 个素材**。图片、视频、音频每种都要通过可公开访问的 URL 传入（本地图片脚本会自动转 base64 data URL）。

> **注意**：上面是**输入参考素材**的体积限制，**不是输出 video 的体积限制**。整个请求体 base64 编码后 ≤ 64 MB，脚本 client 侧 hard-fail 在 60 MB（留 4MB 余量）。详细见 [key-constraints.md](key-constraints.md) 的「输入参考素材 size 限制」一节。

## API 中如何传入

### content 数组结构

```json
{
  "content": [
    {"type": "text", "text": "提示词..."},
    {"type": "image_url", "image_url": {"url": "https://..."}, "role": "reference_image"},
    {"type": "video_url", "video_url": {"url": "https://..."}, "role": "reference_video"},
    {"type": "audio_url", "audio_url": {"url": "https://..."}, "role": "reference_audio"}
  ]
}
```

### 提示词中如何引用

提示词中必须用 `图片n`/`视频n`/`音频n` 格式（n 为该类素材在 content 数组中的排序，从 1 开始），**不支持 Asset ID 直接指代**。

```
参考图片1中的角色面部，参考视频1中的运镜方式，使用音频1作为背景音乐
```

## 四种功能角色

按功能分工组织素材，每种 1-2 个即可，**不要用满上限**：

| 功能角色 | 素材类型 | 作用 | 推荐数量 |
|---|---|---|---|
| 角色锚定 | 图片 | 锁定角色五官/服装/体型 | 1-2 张（大头照 + 全身照）|
| 场景定调 | 图片 | 锁定环境、光源、色调、美术风格 | 1 张 |
| 运镜参考 | 视频 | 锁定镜头语言、动作节奏、构图方式 | 1 段 |
| 氛围音频 | 音频 | 控制情绪基调、背景音类型、旁白音色 | 1 段 |

**黄金配比：4-5 个素材**。过多会导致特征优先级混乱、风格冲突、主体识别模糊。

## 各参考类型详解

### 图片参考（reference_image）

适用场景最广，角色/场景/风格/构图/Logo/道具都可以用图片传。

| 参考类型 | 说明 | 提示词示例 |
|---|---|---|
| 主体多视角 | 同一个角色的面部 + 全身 + 侧面 | `参考图片1的面部、图片2的全身，生成她走路的场景` |
| 场景参考 | 锁定背景、光影、时间 | `参考图片3的场景风格，将人物放置在类似环境中` |
| Logo 参考 | 在画面固定位置展示品牌标识 | `画面右下角始终显示图片5中的标识` |
| 商品 3C | 多角度产品图 | `提取图片1、图片2、图片3中的相机，以相机为主体缓慢旋转` |
| 多宫格分镜图 | 四格/九格漫画式参考 | `参考图片中的分镜图，按照顺序生成相应镜头` |
| 多元素参考 | 角色 + 服装 + 场景 + Logo 组合 | `场景设定在图片4的餐厅内，图片1的女孩身着图片2的服装，图片5的标识始终显示在右下角` |
| 风格/样张参考 | 锁定美术风格和色调 | `参考图片1的赛博朋克风格，生成都市夜景` |

### 视频参考（reference_video）

| 参考类型 | 说明 | 提示词示例 |
|---|---|---|
| 动作参考 | 提取视频中人物的运动方式和节奏 | `参考视频1的人物动作，生成张三在同样节奏下出拳` |
| 运镜参考 | 提取视频中的镜头运动和构图 | `参考视频1的运镜，做成科技园区的概念视频` |
| 特效参考 | 提取粒子效果、光效等的形态和运动逻辑 | `参考视频1的金色粒子特效，让角色身边环绕一样的特效` |
| 风格/氛围参考 | 提取色调、镜头感、画面调性 | `全程使用视频1的第一视角构图和有质感的画面风格` |

### 音频参考（reference_audio）

| 参考类型 | 说明 | 提示词示例 |
|---|---|---|
| 背景音乐 | 情绪、节奏、配器风格 | `全程使用音频1作为背景音乐` |
| 音色参考 | 旁白/角色的声线、音色特征 | `使用音频1低厚温润带细碎颗粒感中年男声的音色` |
| 环境音效 | 提取音频中的环境声氛围 | `环境音效与音频1自然融合` |

## 模式互斥规则

三种生成模式**互斥**，不能在一次请求中混用：

| 模式 | 使用的 role | 典型场景 |
|---|---|---|
| 首帧/首尾帧 | `first_frame`、`last_frame` | 图生视频，精确控制起始/结束画面 |
| 多模态参考 | `reference_image`、`reference_video`、`reference_audio` | 从素材中提取元素生成全新视频 |
| 视频编辑/延长 | `reference_video`（不带 `reference_` 前缀，直接指代 `视频N`） | 在原视频基础上修改或延长 |

**注意**：多模态参考模式中，可以通过提示词指定参考图片作为首帧/尾帧，间接实现"首尾帧 + 参考"效果。但如果需要严格保障首尾帧与指定图片一致，优先使用图生视频-首尾帧模式。

## 视频编辑与延长

### 编辑视频

在原视频基础上修改，`reference_video` 角色的素材就是待编辑的视频：

| 操作 | 提示词示例 |
|---|---|
| 增加元素 | `在视频1的台面上添加炸鸡、披萨等小吃` |
| 删除元素 | `清除视频1桌面上的零件和工具，保持桌面整洁` |
| 修改/替换 | `将视频1中的香水替换成图片1中的面霜，运镜不变` |
| 局部重绘/修复 | `将视频1中的墙壁重新粉刷成白色，保持其他元素不变` |

### 延长视频

在时间维度上延伸视频，最多 3 段视频串联，总时长 ≤ 15 秒：

| 操作 | 提示词示例 |
|---|---|
| 向后延长 | `生成视频1之后的内容，角色继续说{这段台词}` |
| 向前延长 | `向前延长视频1，给角色一个过肩镜头，他说：{这句台词}` |
| 轨道补齐 | `视频1 + 树叶落地金色粒子特效 + 接视频2` |

## 虚拟人像与授权素材（asset:// 协议）

Seedance 2.0 不支持直接上传含真人人脸的参考图。平台提供两种方案：

| 方案 | 用法 | 收费 |
|---|---|---|
| 预置虚拟人像库 | `image_url.url: "asset://<asset-id>"` | 免费 |
| 已授权真人素材 | 录素材入库后使用 asset:// 协议 | 免费 |

**注意**：Asset ID 仅用于 content 中的 url 字段，提示词中仍需用 `图片n` 引用。

## 本地文件处理

| 文件类型 | 支持方式 |
|---|---|
| 本地图片（PNG/JPG/WebP） | ✅ 脚本自动转 base64 data URL |
| 本地视频（MP4/MOV） | ❌ 需先上传到可公开访问的 URL 或 TOS |
| 本地音频（MP3/WAV） | ❌ 需先上传到可公开访问的 URL 或 TOS |

## 参考素材最佳实践

1. **素材越重要，提示词中越靠前**。越精准参考的素材，放在提示词越靠前的位置。
2. **人脸参考用大头照 + 全身照，不用三视图**。三视图易导致人物重复或 ID 漂移。
3. **参考人物 ≤ 4 人**。超过 4 人需分组建模。
4. **不要用直接剪映/剪辑后的视频做参考**。剪辑、压缩、转发可能破坏元数据，导致素材失效。
5. **视频 URL 24 小时过期**。长期保存建议转存到火山引擎 TOS。
