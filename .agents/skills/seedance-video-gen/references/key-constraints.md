# Seedance 2.0 关键约束速查

30 秒扫完这个文件，就知道能力边界、常见翻车和避坑方法。写提示词细节读 `prompt-guide.md`，场景示例读 `scene-cookbook.md`。

## 音频能力速查

| 能力 | 说明 |
|---|---|
| ✅ 音视联合生成 | `generate_audio=true`（脚本默认；官方未明文 API 默认值），画面、对白、音效、背景音一次生成 |
| ✅ 口型对齐 | 模型自动匹配台词与口型，支持 ≥8 种语言 |
| ✅ 多语言旁白 | 中/英/日/韩/法/西班牙等，小语种在 `{}` 中标注语种 |
| ✅ 环境音效 | 雨声、风声、脚步声、Foley 等，在提示词中用 `<>` 指定 |
| ✅ 背景音乐 | model 可根据 `（）` 中描述自动生成伴奏 |
| ✅ 单声道 mono | 输出音频为单声道，与输入音频声道数无关 |
| ❌ 纯音频输入 | 音频不能单独作为 content，必须配 ≥1 图或 ≥1 视频 |
| ❌ 参考音色不准 | 音色漂移风险：需在提示词中补充细致音色特征描述 |

## 能力矩阵

### 能做什么

| 能力 | 说明 |
|---|---|
| ✅ 文生视频 | 仅文本描述生成，最长 15s |
| ✅ 图生视频（首帧） | 一张图 + 描述，role=`first_frame` |
| ✅ 图生视频（首尾帧） | 两张图 + 描述，role=`first_frame` + `last_frame` |
| ✅ 多模态参考 | 文本 + 图（0-9）+ 视频（0-3）+ 音频（0-3），任意组合，最长 15s |
| ✅ 编辑视频 | 替换主体、增删改元素、局部重绘/修复 |
| ✅ 延长视频 | 向前/向后延长，或轨道补齐（最多 3 段视频串联，总 15s） |
| ✅ 生成有声视频 | `generate_audio=true`，音视联合生成，支持旁白/台词/音效，最长 15s |
| ✅ 4k 输出 | 仅标准版 `doubao-seedance-2-0-260128`；10-bit H.265/HEVC 编码，并发 1、RPM 15 |
| ✅ 文字生成 | 广告语、字幕（需同步音频节奏）、对话气泡 |
| ✅ 联网搜索 | `tools: [{"type":"web_search"}]`，仅纯文本输入（见下方约束） |
| ✅ 返回尾帧图 | `return_last_frame=true`，用于链式续写 |

### 不能做什么

| 限制 | 说明 |
|---|---|
| ❌ 真人脸输入 | Seedance 2.0 系列不支持上传含**任意**真人人脸的参考图/视频（不限公众人物）。可用预置虚拟人像（asset://）、已授权真人素材、或 Seedream 5.0 lite 生成的人脸 |
| ❌ 纯音频输入 | 音频不能单独作为 content，必须配至少 1 张图或 1 段视频 |
| ❌ 首尾帧 + 多模态参考图混用 | `first_frame`/`last_frame` 与 `reference_image` 互斥；与 `reference_video`/`reference_audio` 共存未在官方文档明文确认（详见 multimodal-reference.md「模式组合规则」） |
| ❌ Fast / Mini 版 1080p/4k | `doubao-seedance-2-0-fast-260128` 和 `doubao-seedance-2-0-mini-260615` 最高 720p |
| ❌ 超过 4 个参考人物 | 同一请求中参考人物建议 ≤ 4 人，更多需分组生成 |
| ❌ 精确时间控制 | 模型对精确秒数（如 0-3 秒）不稳定，优先让模型自然生成节奏 |
| ❌ 跨账号素材 | 信任产物仅限同账号、同一模型线、30 天内 |
| ❌ 本地视频 base64 | 视频输入仅接受 http(s):// URL 或 asset:// ID，不支持 base64 data URL（图片和音频支持） |

### 速率限制

> ⚠️ **官方文档与实测有出入**。普通 720p/1080p 数据来自 2026-06-18 的实测；4k 数字来自 2026-06-25 官方文档（尚未独立 benchmark）。
> 关键认知：**submit 任务（POST /tasks）实测不限流**（普通公司开发账号），可以批量 burst 提交。并发限制的是**同时在 running 状态的 task 数量**——超出后新任务进 `queued` FIFO 排队，不会报 429。官方文档列出企业 600 / 个人 180 RPM，个人账号未验证。

| 维度 | 官方声明（普通） | **实测（普通公司开发账号）** | 4k | 备注 |
|---|---|---|---|---|
| Submit 端 QPS / RPM | 文档列出企业 600 / 个人 180 RPM | **实测无限流**（70 fast + 30 standard 并发 0 个 429，峰值 75 req/s 也无问题） | **15 RPM** | 4k 限流严格，其余档位文档数字偏保守 |
| 同时 running 上限 | 企业 10 / 个人 3 | **稳定 20**（fast + standard 共享 pool） | **1** | 普通档位官方数字严重低估（实测 2x）；4k 真的只有 1 |
| Standard vs Fast slot pool | 未明确 | **共享同一 20-slot pool** | 独立 | 普通档位一个模型占满会影响另一个 |
| 排队行为 | 未明确 | 超过容量后入队，FIFO | FIFO | 完成一个进一个 |

**账户上下文**：本数字是 Erik 的**普通公司开发账号**（非火山 VIP 企业账号）实测结果。
按官方模型列表的"企业/个人"划分，本账号属于"企业"档（应为 10），但实测拿到 20。
意味着**官方数字对所有非 VIP 账号都偏低**。个人账号是否也 20 未验证。

**实操建议**：
- 批量提交 720p/1080p 不需要 sleep / 退避，一次 burst 几十个 task 没问题
- 4k 任务严格串行（RPM 15 + running 1），提交后做好长时间等待
- 监控 running 数用 `generate_seedance_video.py list-tasks --status running`
- 想测真实 cap 至少要等 60-90s（cap 是动态的，初始 10 然后涨到 20）
- 想要长视频多镜：使用 `batch-submit` 一次提交所有分镜

详细数据、方法和后续 todo 见 [benchmark 报告](../../../docs/benchmark/seedance-concurrency-benchmark.md)（从 skill 内引用走相对路径 `../../../docs/benchmark/`）。

## 联网搜索 web_search 约束

| 维度 | 规则 |
|---|---|
| 启用 | `tools: [{"type": "web_search"}]`（脚本：`--enable-web-search`） |
| content 类型 | **只能有 1 个 `text`**，不能有 image_url / video_url / audio_url |
| 多模态 + 搜索 | 互斥；脚本会在 client 侧硬拦截并报错 |
| 适用模型 | Seedance 2.0 系列（其他模型线不支持 `tools` 字段） |
| 调用次数 | **由模型自主决定**，可能 0 次（信息够就不搜），也可能多次 |
| 延迟影响 | 增加生成等待时间（要等搜索结果返回后才开始视频生成） |
| 计费 | `usage.tool_usage.web_search` 反映实际调用次数 |
| 适合场景 | 引用当前事件 / 最新数据 / 新闻 / 股价等模型权重外信息 |

> 多模态 + web_search 互斥是官方硬约束。如果素材需要联网搜索引用，建议**先用 web_search 跑一次纯文生视频**，再以产出的视频作为 `reference_video` 用第二轮无 web_search 的请求续写。开启 web_search 但模型判断不需要搜索时不会报错，只是按普通文生视频走。

## 实测生成时间（100 个真视频样本，2026-06-18）

> 单 task 从 submit 到 succeeded 的 wall time（包含队列等待）。

| 模型 | 时长/分辨率 | median | mean | p95 | max |
|---|---|---|---|---|---|
| Fast | 4s 480p | **249s** (~4.2 min) | 266s | 476s | 511s |
| Standard | 5s 720p | **274s** (~4.6 min) | 279s | 493s | 508s |

**关键结论**：
- **一个 4s 短视频实际需要 ~4 分钟**生成
- Fast 和 Standard 时间几乎一样（差 10%），fast 优势在 token 成本
- Token 用量固定：fast 40594 / standard 108900（同一参数下所有 task 一致）
- 写文章/做 demo 时**预估 4-5 min/段**算等待时间

## 输入参考素材 size 限制

> **重要**：这些是**输入参考素材**的体积上限，**不是输出 video 的体积限制**。
> 输出 video 的大小由模型决定，API 不限制（只受 TOS 24h URL 有效期约束）。

| 素材类型 | 单文件上限 | 传输方式 | 支持格式 | 备注 |
|---|---|---|---|---|
| 参考图片（`first_frame` / `last_frame` / `reference_image`） | **30 MB** | base64 data URL / http(s) URL / asset:// | PNG / JPG / JPEG / WebP / GIF / BMP / TIFF / HEIC / HEIF | 本地图片脚本自动转 base64 |
| 参考视频（`reference_video`） | **200 MB** | **仅 http(s) URL 或 asset://（不支持 base64）** | **仅 MP4 (.mp4) / MOV (.mov)**；视频编码 H.264/AVC 或 H.265/HEVC；容器内音频 AAC 或 MP3；FPS ∈ [24, 60]；分辨率 480p~4k（总像素 [409600, 8295044]，单边 [300, 6000] px，宽高比 (0.4, 2.5)） | 本地视频需先上传公网 bucket |
| 参考音频（`reference_audio`） | **15 MB** | base64 data URL / http(s) URL / asset:// | **仅 WAV / MP3**（官方明文支持）；其他格式（AAC/FLAC/M4A/OGG 等）请先转码为 WAV/MP3 | 本地音频脚本自动转 base64 |
| **整个请求体** | **64 MB** | — | — | base64 编码后膨胀 ~33%，脚本 client 侧 hard-fail 在 60 MB，留 4 MB 余量 |

**音频时长限制**：

| 维度 | 限制 |
|---|---|
| 单个音频时长 | [2, 15] s |
| 音频数量 | ≤ 3 段 |
| 总音频时长 | ≤ 15 s |

**参考素材像素 / FPS 硬约束**（官方）：

| 维度 | 图片 | 视频 |
|---|---|---|
| 宽高比（宽/高） | (0.4, 2.5) | (0.4, 2.5) |
| 单边长度（px） | [300, 6000] | [300, 6000] |
| 总像素 | — | [409600, 8295044]（≈ 480p ~ 4k） |
| FPS | — | [24, 60] |
| 编码 | — | H.264/AVC 或 H.265/HEVC，推荐 H.264 |
| 容器内音轨 | — | AAC 或 MP3 |

> 这些是 API 层硬约束，触线会被 400 InvalidParameter 拒绝。脚本会在 client 侧检查文件大小，但不会做像素维度 preflight；如果素材来自自动 pipeline 建议加一道 ffprobe 校验。

**实操建议**：

- 本地图片和本地 mp3/wav 音频脚本会自动转 base64 data URL；**本地视频必须先上传到公网 URL 或用 asset:// 素材**
- 视频大文件（> 100MB），建议先传到自己的公网 bucket（TOS / S3），用 URL 形式传入
- 一次请求里图片 ≤ 9 + 视频 ≤ 3 + 音频 ≤ 3（官方未明文规定总数硬上限；**脚本 client 侧硬限总计 ≤ 12**）。**实测推荐 4-5 个素材的黄金配比**（见下），不要用满单类型上限
- 单个文件超限 → 脚本直接报错并退出；请求体超 60MB → 脚本直接报错；不要等 API 返回 400

## Seedance 2.0 系列暂不支持的参数

| 参数 | 原因 | 替代方案 |
|---|---|---|
| `seed` | 2.0 系列**入参不支持**（无法主动复现） | 用 prompt 锁定视觉风格描述；响应里会返回服务端实际使用的种子值，仅供事后 traceability，不能回填作为入参复用 |
| `camera_fixed` | 2.0 系列不固定摄像头 | 改用 prompt 写「固定机位 / 锁镜头 / tripod shot」 |
| `frames` | 2.0 系列暂不支持 | 用 `duration` 整数秒 |

> `frames` 是官方为小数秒输出设计的，但 2.0 暂未开放；如果脚本传入 `frames` 字段，API 会拒绝。


## 任务 ID 与 URL 保留期（重要）

| 资源 | 保留期 | 超期后 |
|---|---|---|
| 任务 ID（succeeded/failed/expired） | **7 天**（从 `created_at` 起算） | 自动清除，`GET /tasks/{id}` 返回 404 |
| 任务 ID（cancelled） | **24 小时** | 自动清除 |
| 任务列表 | 7 天 | 列表为空 |
| 视频 URL | **24 小时** | 失效，无法下载 |

> 这是 7 天 vs 24 小时的常见混淆点：任务记录能查 7 天，但视频 URL 在 24 小时后就没了。**cancelled 任务只保留 24 小时**。
> **生成成功立即下载**，并配置 TOS 数据订阅自动转存到自己的桶。


## 素材配置黄金配比

| 角色 | 作用 | 数量 | 格式 |
|---|---|---|---|
| 面部特写 | 锁定人物五官（大头照，仅面部，无表情） | 1 张 | PNG/JPG/WebP |
| 全身照 | 锁定服装、体型、整体外观 | 1 张 | PNG/JPG/WebP |
| 场景图 | 锁定环境与风格 | 1 张 | PNG/JPG/WebP |
| 运镜参考 | 锁定镜头语言与动作节奏 | 1 段 | MP4/MOV |
| 背景音/氛围音 | 控制情绪与节奏 | 1 段 | MP3/WAV |

**总计 4-5 个素材即可，不要用满单类型上限**。过多素材会导致特征优先级混乱、风格冲突、主体识别模糊。

## 人脸处理策略

| 场景 | 方案 |
|---|---|
| 不需要指定具体人物 | 使用预置虚拟人像库（`asset://<asset-id>`，免费） |
| 需要真人授权 | 录素材入库后使用 asset:// 协议 |
| 二创自己生成过的视频 | 同账号 30 天内信任产物（包括 Seedance 产出的尾帧图），可作为输入 |
| 需要 AI 生成人脸 | Seedream 5.0 lite 生成的人脸图可作为参考输入（2026-04-16 起支持） |
| 仅概念/氛围视频 | 不加人脸参考，纯文本生成（安全免审核） |

**重要**：asset:// 仅用于向模型传入素材，提示词中仍需用 `图片n`/`视频n`/`音频n` 格式引用，不支持直接用 Asset ID 指代。asset:// 同时支持图片、视频、音频三种 role。

## 信任产物（同账号可作为输入）

| 产物类型 | 有效期 | 来源模型线 | 生效日期 | 备注 |
|---|---|---|---|---|
| Seedance 产出的含人脸视频 | 同账号 30 天内 | Seedance 2.0 系列 | **2026-03-11 起** | 可作 reference_video |
| Seedance 产出的尾帧图（`return_last_frame`） | 同账号 30 天内 | Seedance 2.0 系列 | **2026-04-16 起** | 可作 reference_image |
| Seedream 5.0 lite 文生图含人脸图 | 同账号 30 天内 | Seedream 5.0 lite | **2026-04-16 起** | 可作 reference_image |

> **硬约束**：仅信任**原始产物**。跨账号 / 跨平台 / 二次剪辑 / 压缩转发 / 超过 30 天均失效。建议把信任产物原始 mp4 / png 第一时间转存到自己的 TOS bucket 保留副本，转发渠道里压过的版本不能再用。

## 常见翻车清单

| 现象 | 一句话解法 |
|---|---|
| 人物撞脸明星/中途换脸 | 额外准备大头照、提示词前置、不用三视图 |
| 视频自动带字幕 | 加 `保持无字幕`、优先横屏、参考素材去文字 |
| 2D/3D 风格漂移成真人 | 提示词加 `2D日漫风格` 或 `3D国风漫画`，参考图先转风格 |
| 画面出现双胞胎 | 明确角色-参考图绑定、末尾加分身禁止约束、不用三视图 |
| 延长衔接处跳变 | 前段删 6 帧 + 后段删 1 帧，以转场切镜结尾 |
| 延长后画质劣化 | 产出先转白模视频再续写，优先高清参考，避免多次续写 |
| 特效不符合预期 | 用参考视频定义特效，不靠文字描述复杂特效 |
| 参考人物超过 4 人 | 分组生成图片（每组 ≤ 4 人），再图生视频 |
| 视频结尾有噪音 | 剪映音量包络线末尾下拉至 0，做音频淡出 |
| 中文多音字发音不准 | 替换为同音常用字，如 "螭龙山" → "吃龙山" |
| 音色与参考音频不匹配 | 补充音色特征描述，保持视频台词风格与参考音频一致 |
| 首帧图生视频画面跳变 | ratio 设为 `adaptive`，或预裁剪图片到目标宽高像素值 |

## 特殊符号约定

| 信息类型 | 符号 | 示例 |
|---|---|---|
| 音乐 | `（）` | `（背景中播放着快节奏的摇滚乐）` |
| 音效 | `<>` | `<远处传来狗叫声>` |
| 台词 | `{}` | `{你好，世界}` |
| 小语种台词 | `{}` + 标注 | `用日语说道{こんにちは}` |
| 字幕 | `【】` | `【第一章：启程】` |

## 视频存储与有效期

- 生成的 `video_url` **24 小时有效**，必须立即下载到本地
- 推荐配置 TOS 数据订阅，自动转存到自己的桶中
- 信任产物（同账号 30 天内）可直接作为输入素材，压缩/转发/二次剪辑或超期后失效
