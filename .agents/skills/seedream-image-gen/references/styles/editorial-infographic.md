# 信息图 / 毛玻璃数据卡 (Editorial Infographic / Photo + Data Cards)

> 一整张真实摄影质感的 hero 底图，叠加若干半透明毛玻璃数据卡片 + 顶部大标题 + 独立横带时间轴，整体呈现 National Geographic 跨页 / Bloomberg 数据新闻 / 政府科研报告封面的编辑质感。典型应用是南极科考站、高铁复兴号、野生动物迁徙、新能源基地、航天发射、气候数据等"强主体摄影 + 关键数据点"的解释型信息图。下方 Recipes 提供可直接 copy-paste 的 winning recipe。

适合：16:9 宽幅数据新闻信息图、3:4 竖版社交配图（小红书/IG 科普）、科研/政府/企业报告封面、科普类文章头图、品牌白皮书插页。

不适合：
- **像素级精确的数据图表**：AI 出的柱状/折线/环形图只是"像图表"，不是精确 dataviz——需要精确数值对照、正确坐标轴、可交互分析的图一律用 ECharts / Chart.js / matplotlib / `dataviz` 技能渲染后 Figma/PS 合成。
- **长段落文字**：2 行以上中文导语、脚注、来源说明必乱码。
- **需要具体精确数字对照的正式报告**：数字"大概对"，不做精确 KPI 比对。
- **像素级还原特定真实建筑/地点**：AI 的"秦岭站""外滩"是大众印象，不是测绘级准确；要精确还原请传 `--reference-image` 实拍图（img2img 会覆盖建筑身份，见翻车提醒 #7）。
- **卡片超过 6 张的密集排版**：横版硬上限 6 张，竖版硬上限 5 张，超过必重叠/乱码。

**Pro 专属风格。** Lite 可出概念草图但毛玻璃质感、中文字体、图表细节明显发糊，正式交付一律 Pro 2K。横版默认 `--wide`（1792×1024，Seedream Pro 原生宽幅）；竖版 `--portrait`（1536×2048）。

## 结构 Guardrails

### 1. 画幅 / 尺寸

| 用途 | Flag | 分辨率 | 卡片上限 |
|---|---|---|---|
| 横版 16:9 宽幅（公众号头图 / 博客 hero / PPT 封面 / 报告封面，默认） | `--wide` | 1792×1024 | **≤ 6 张**（2+3+1 或 2+2+1 布局） |
| 竖版 3:4（小红书 / IG / 抖音科普图文） | `--portrait` | 1536×2048 | **≤ 5 张**（text garble 约 2× 于横版） |
| 极简版（PPT 单 KPI 卡） | `--wide` | 1792×1024 | 3 张 |

输出 `png`（lossless，图表/文字锐利度必需）；`watermark=false`；web-search 关（会拉风格不一致的参考图打架）。best-of-N 建议 **生成 2-4 张**挑文字最干净的；同 prompt 不同次生成间文字准确度有波动。

### 2. 底层 Hero 照片（不写照片就变 3D 渲染，这是最致命的翻车点）

必须显式写**摄影关键词 + 相机锚点 + 风格锚点 + 反例防御**四件套，否则模型默认出 CGI/科幻钻石形建筑。

**关键词组合（缺一不可）**：
```
全画幅高清航拍/编辑照片:{{HERO_PHOTO_DESCRIPTION}},
Christopher Michel National Geographic Program photo 质感,
{{TIMELINE_YEARS_EXTRA_CONTEXT}};
明亮 cold-but-bright daylight（或 golden-hour warm light，随主题）,
shot on Phase One IQ4 150MP;
主体位于画面正中 dead-center（纵向 30-85%、横向 20-80%）,
四周留空给浮层卡片。
禁止CGI渲染感、禁止科幻未来感、禁止3D渲染、禁止卡通插画、禁止游戏截图、
禁止红色屋顶、禁止金色镜面反光、禁止过度抛光。
```

要点：
- **必须出现 "全画幅高清…照片" + 一个杂志/通讯社风格锚点**（`National Geographic Program photo` / `Bloomberg data journalism hero photo` / `Reuters news feature photo` 任选其一）+ 一个具体相机/机身锚点（`Phase One IQ4 150MP` / `Sony A1 50MP` / `Hasselblad X2D` 任选其一）。
- **显式列禁止项**（"禁止CGI…"）。只写正向词不够，必须加负向防御。
- 主体位置显式锁 `dead-center (纵向 30-85%、横向 20-80%)`，给周围留卡片区。
- 光线词给英文术语最稳（`golden-hour warm light` / `soft overcast daylight` / `cold-but-bright polar daylight` / `cinematic rim light`）。

### 3. 毛玻璃卡片 spec（signature 元素，关键词必须逐字准确）

这是整个风格最核心的部件，关键词差一个字就会出实心白卡 / 纸张 / 亚克力板。**关键词组合**：

```
frosted white glass 毛玻璃效果 iOS control center 风格,
rgba(255,255,255,0.7) 白色填充,
backdrop-blur 约 24px（必须能清晰透过卡片看到背后的场景）,
1px rgba(255,255,255,0.4) 浅白描边,
16px 圆角,
柔和投影
```

配套规则：
- **卡片内文字**：深 slate 灰 `#1E293B`，中文无衬线黑体，数字 tabular numerals；
- **卡片内文字量硬约束**：短标题 ≤6 字中文 + 阿拉伯数字 + 1-2 字中文单位，**禁止完整句子、禁止 2 行以上段落、禁止抒情导语**；
- **禁止清单必须写**：`禁止实心不透明白色、禁止纸张/卡纸/亚克力板质感、禁止不透明度超过 70%`；
- **卡片数量硬上限**：横版 ≤6、竖版 ≤5。6 张横版布局建议 `2 (左上叠) + 3 (右上/中/下) + 1 (底部横条)`，底部横条是设备/部件缩略图条，占纵向 16-18%；
- **卡片位置必须显式给百分比**，不要让模型自由放：例如 `- 卡片1 左上角 (x:3%, y:23%, 宽22%, 高22%): ...`；
- **中央保护区（No-Card Zone）**：**画面中央 40% 宽 × 55% 高矩形区域（纵向 30-85%、横向 20-80%）绝对禁止任何卡片侵入**，卡片与主体轮廓之间留 ≥3% 画面宽度空白呼吸带；卡片间距 ≥2%。这行是防止卡片覆盖主体的关键约束，必须逐字写。

### 4. 标题 / 时间轴 spec

**主标题 masthead（画面顶部）**：
```
画面顶部居中（纵向 3-12%）,
超大号白色中文粗黑体大标题「{{TITLE}}」
（字号占画面高度 1/7, 粗黑无衬线 PingFang/思源黑体风格,
印刷锐利, 字迹准确无错字, 用「」引号包裹逐字写出）;
大标题正下方一行大号白色英文无衬线副标题 "{{ENGLISH_SUBTITLE}}"
（字号 ≥ 大标题 1/3, geometric sans-serif, 全部大写,
这是画面唯一的英文文字, 不加其他英文小字、不加作者栏）。
这两行之外不再加中文导语或英文介绍。
```

要点：
- 中文主标题**必须用「」引号逐字包裹**，字号占比 1/7（不是 1/6 也不是 1/8），位置纵向 3-12%。
- 副标题**只保留一行英文**；中文两行以上导语必 garble。
- "这两行之外不加其他" 是防止模型乱加作者栏/期号/来源小字。

**时间轴（独立横带，不放在卡片里）**：
```
标题正下方、所有卡片上方（纵向 13-22% 独立横带）,
一条白色水平细线贯穿画面宽度 90%,
连接恰好 {{N}} 个白色圆点节点,
圆点上方是彩色极简小图标 glyph（配色区分年代, 允许抽象彩色圆点代替）、
圆点上方印白色年份阿拉伯数字、
圆点下方印白色中文站名/里程碑名,
右端细小白色箭头。
{{TIMELINE_YEARS 逐字列出：① 1985 长城站 / ② 1989 中山站 / ...}}。
恰好 {{N}} 个节点, 不重复, 不放在卡片里, 不用柱状图横轴代替。
```

要点：
- 开头写"恰好 N 个"，结尾再写"恰好 N 个，不重复"双重防御；单写一次不够。
- **每个节点逐字列出**：年份 + 名字，不要让模型自己分配。
- **不要用柱状图横轴代替时间轴**，不要把时间轴塞进卡片里——它是 masthead 的一部分。
- Mini-icons 容易渲染成随机 emoji 或乱涂；稳妥做法是允许"抽象彩色圆点"代替具象图标。

### 5. 图表描述公式（"recognizable charts"，不是精确图表）

所有图表都要**显式指定"图表类型 + 数据摘要 + 颜色"**，不要让 AI 自由发挥。最稳写法：

| 图表类型 | 最稳写法 | 翻车点 / 防御 |
|---|---|---|
| **柱状图 bar** | `N 根{{COLOR}}色柱体，从左到右：{{NAME1}} {{V1}}、{{NAME2}} {{V2}}…（明确写出最矮/最高/第二高的相对关系："{{MAX_NAME}} {{MAX_V}} 最高、{{MID_NAME}} {{MID_V}} 第二高、{{MIN_NAME}} {{MIN_V}} 最矮，数字是 {{MIN_V}} 不是 {{MIN_V}}0 不是 {{MIN_V}}4 不是 {{MIN_V*10}}"）；柱顶直接标数值+中文单位，**不画 y 轴刻度**` | Y 轴单位必乱（558→5584/5580/258/558米）——最稳是不画 y 轴，柱顶直接写数值；显式给相对排序和"数字是 X 不是 X0/X4"防御。x 轴标签 ≤3 字中文站名/类别名，禁止 J/F/M 英文月份。 |
| **甜甜圈 donut** | `严格 2 段环形甜甜圈图（不要第三段、不要小切片）：{{SEG1}} {{P1}}%（{{COLOR1}}）、{{SEG2}} {{P2}}%（{{COLOR2}}），两段相加精确 100%；中心白孔只写「{{SHORT_LABEL}}」2-4 个汉字（不写百分比数字、不写英文）；两段外侧直接白色引线标注` | 多段必出灰色"其他"切片——必须写"严格2段、不要第三段、不要小切片"。中心百分比数字必与图例自相矛盾——中心只放 2-4 字主题词，不写百分比。 |
| **折线图 line（高风险）** | `一条{{COLOR}}色折线，不画坐标轴、不画刻度数字；在曲线最高点旁标注「{{PEAK_LABEL}}」、最低点旁标注「{{VALLEY_LABEL}}」，其他位置不印数字或月份名` | X 轴月份必乱码（常出现"J 3 A A 5 G..."这类字符）——最稳做法是**完全不要坐标轴**，用 shape + 两个 callout 传达趋势。特殊主题（南极极昼）必须显式给形状：`南极单谷 V 形——12/1 月 ≈22-24h 极昼、6 月 ≈0h 极夜，只有一个波谷在 6 月`。 |
| **编号步骤流程（高风险）** | **推荐 (a) 无编号图标列表**（最稳）：`N 个极简线图标 + 每项 ≤4 字中文标题，水平横向单行排列，不加编号圆圈、不加连接箭头`。<br>必须编号时 (b)：`N 个编号圆圈从 ① 到 {{N}} 严格水平横向排列成单行，编号连续不跳不重——禁止重复④、禁止跳过⑤⑥、禁止 N-1 步、禁止 N+1 步：①{{LABEL1}} ②{{LABEL2}} … {{N}}{{LABELN}}；每步一个极简线图标 + 4 字中文标题` | 编号必跳号/重复/错序、图标易变涂鸦——最稳是不编号；编号必须逐字列出全部序列并加"禁止重复/跳过"。 |
| **设备/缩略图横条** | `横排 N 张小图（{{ITEM1}}/{{ITEM2}}/…），每张图下方不加中文标签；卡片顶部一行 4-6 字总标题` | 缩略图下方 label 90% 乱码——最稳是不做单图标签。必须标签时每张 ≤4 字中文。 |

### 6. 配色 palette（冰蓝/青绿/雪白/深青默认；可换 accent）

| 用途 | 色值 | 说明 |
|---|---|---|
| 主色（柱/线/图表） | 冰蓝 `#2C7A95` | 冷调科研/南极/海洋默认 |
| 深色（标题背景/卡片强调） | 深青 `#0F4C5C` | 暗色块/底部渐变 |
| 辅助色（第二柱体/图例） | 青绿薄荷 `#4ECDC4` | 数据强调 |
| 卡片填充 | `rgba(255,255,255,0.7)` | frosted white glass |
| 卡片描边 | `rgba(255,255,255,0.4)` 1px | 浅白细边 |
| 卡片内文字 | slate-800 `#1E293B` | 深 slate 灰 |
| 顶部标题/时间轴文字 | 纯白 `#FFFFFF` | masthead 反白 |
| Accent（暖主题替换） | 中国红 `#C41E3A` / 暖金 / 品牌 VI 色 | 高铁/节日/品牌报告时替换冰蓝主色，毛玻璃白卡保持 neutral |

冷色调（蓝/青/雪/冰/夜空）信息图最出效果；暖色主题（高铁/夕阳/春运/节日）只换主色和 hero 光线（`golden-hour warm light`），毛玻璃白卡中性不变。

### 7. 字体 / 中文字体族

- 中文：**粗黑无衬线（PingFang / 思源黑体风格）**——不要写具体字体文件名（模型不认识思源黑体/方正兰亭），写族名"粗黑无衬线"。
- 英文副标题：`geometric sans-serif (Futura / Helvetica-style)`，全部大写。
- 数字：`tabular numerals（等宽数字）`——数据卡必备。
- 所有出现的中文文字必须在 prompt 里**逐字写出**，不要让模型自己编。
- 中文正文约束：单条文字 ≤6 字最稳（短标题/标签/单位），>8 字错字率陡增。

### 8. AI 瑕疵规避（inline 禁止指令 + negative_prompt 双保险）

**Prompt 末尾 inline 禁止指令（belt）**——这些是必须逐字加的：
```
禁止同字重复（"极极""钻钻"）、禁止近形字替换、禁止造字、禁止同音字替换；
除了副标题那一行英文外其他位置一律只用中文,
禁止英文缩写（把 GNSS/CNSS 等写成中文）,
禁止 J/F/M/A 英文月份缩写、禁止纯数字月份如 "5j""19"、禁止拉丁字母坐标轴,
不加脚注/来源/watermark/logo/作者栏/期号;
无水印、无乱码、无错别字、2K 高清。
```

**CLI `--negative-prompt`（加了文字更干净）**：
```
CGI render, 3D render, sci-fi futuristic building, diamond-shaped building,
cartoon, illustration, anime, game screenshot, watermark, logo,
garbled text, gibberish Latin letters, misspelled characters, repeated characters,
J/F/M/A/M/J English month labels, solid white opaque cards, paper texture,
acrylic board, red roof, gold mirror reflection, overexposed white
```

Inline "禁止…" directives alone can produce clean results; adding a neg-prompt makes text even cleaner — **use both, belt and suspenders**.

### 9. Img2img 说明（不推荐作为主 workflow）

- Text-to-image + 强摄影关键词（Christopher Michel + Phase One + 禁止 CGI）可达到很高的照片真实感，**默认不需要 img2img**。
- 如果坚持要用自己的 hero 照片做底，`--reference-image` 可用但参考强度设低（~0.3-0.4），且预期 ~30% 图表退化；照片本身可保留得很好，但建筑身份可能被覆盖、图表形状可能被破坏。Img2img 是 "one-editing-step" 工具，不是 "preserve everything, add overlays"。

## Inspiration Defaults

| 变体 | 默认方向 |
|---|---|
| **横版 16:9（默认）** | hero 摄影 dead-center 占中央 40%×55%，masthead（主标题 + 英文副标题 + 5 节点时间轴）占顶部 22%，左上 2 张叠卡（柱图 KPI + donut 能源结构）、右上 1 张（气象/参数 list）、右中 1 张（流程无编号图标 list）、左下 1 张（折线趋势，无坐标轴，两个 callout）、底部 1 张横条（4 张设备缩略图无标签），冰蓝 `#2C7A95` + 深青 `#0F4C5C` + 青绿 `#4ECDC4` 冷色调，premium data journalism / National Geographic double-truck spread 质感 |
| **竖版 3:4（小红书/IG 科普）** | 顶部 10% masthead（大中文标题 + 一行英文，不做时间轴因为竖版横向空间不够），中上 40% 高 hero 照片，下半 50% 在深蓝 `#0F2C4A` 渐变纯色底上排布 5 张小毛玻璃卡片（3 张 KPI 数字卡 + 2 张短标签卡），卡片对称规整，文字 3-4 字短标题 + 大号阿拉伯数字 + 一行小字说明，**不做图表**（竖版图表坐标轴必乱），卡片填充 `rgba(255,255,255,0.15)`（深色底上透明度调低） |
| **极简 3 卡版** | 顶部左侧 masthead（大标题+副标题），右侧 1 张大 KPI 卡（大号数字 + 一行说明），左下 1 张趋势折线（无坐标轴双 callout），底部 1 张横排 3 图缩略图条，中央 60% 留 hero 照片，适合 PPT 单页封面 / 博客 hero |

> 覆盖规则：用户 brief 指定了具体主题（高铁/藏羚羊/新能源/航天/气候）、品牌 VI 色、或已经自带 hero 照片时，放弃灵感默认，只保留结构 guardrails（摄影四件套、毛玻璃 EXACT 关键词、中央保护区、图表公式、配色替换、字体族、inline 禁止 + neg-prompt、尺寸约定）。

## Recipes

所有 recipe 默认 Pro、2K、`png`、`--wide` 横版（除 Recipe 3 是 `--portrait`）、neg-prompt 用 §8 的推荐版本、`watermark=false`。文字（主标题、时间轴节点名、卡片短标题）**必须用中文引号「」逐字包裹**并指定字体族/字号占比/位置/颜色；单条中文 ≤6 字最稳。一次生成 2-4 张挑文字最干净的。

### Recipe 1：横版 16:9 南极科考信息图（canonical baseline recipe）

```bash
uv run scripts/seedream_image_gen.py generate \
  --wide \
```

纯 text-to-image 出 hero 照片时，人造物（建筑、列车、工业设备）常被渲染成 CGI 棱角科幻感。如果已有一张真实 hero 照片（实拍或之前生成满意的底图），两步 img2img overlay 能保留底图 1:1，同时叠加毛玻璃卡——多一次 API call，但照片真实感显著提升（建筑、雪地车、集装箱、气象塔、冰山、golden-hour 光线可像素级保留）。

**第一步：先生成/选好 hero 照片（或用实拍）**

**第二步：img2img 叠加毛玻璃卡**
```bash
uv run scripts/seedream_image_gen.py edit \
  --reference-image hero-photo.png \
  --wide \
  --negative-prompt "CGI render, 3D render, sci-fi futuristic building, cartoon, illustration, solid white opaque cards, paper texture, acrylic board, garbled text, misspelled characters" \
  --prompt "在这张照片上叠加毛玻璃数据卡片,严格保留底层照片(建筑/车辆/设备/光线/背景)像素级不变、不重绘,只在边缘留白区域加浮层卡片:

[6张毛玻璃数据卡片] 所有卡片浮于四边留白,完全不遮挡中央主体(画面中央40%宽×50%高矩形保护区禁止卡片侵入),卡片与主体轮廓留≥3%空白呼吸带。每张卡片:frosted white glass毛玻璃效果,rgba(255,255,255,0.45)白色填充,backdrop-blur 24px,1px rgba(255,255,255,0.4)浅白描边,16px圆角,柔和投影;卡片内文字深slate灰#1E293B,无衬线黑体,tabular numerals;禁止实心不透明卡片、禁止纸张质感。卡片位置与内容:
- 卡片1 左上:短标题加柱状图;**柱体必须用两种颜色区分每段/高亮关键柱**(不要单色柱群);柱顶直接标数值不画y轴;显式写\"{{KEY_NAME}}柱顶标{{VALUE}},不是{{WRONG_VALUE}}\"锚定关键数值防漂移(如\"中山站柱顶标2700,不是2200\"；昆仑站558不是5584)
- 卡片2 右上:图标+4行数据列表,每行 ≤10 字符中文+数字+单位
- 卡片3 左中:**甜甜圈严格2段,左侧40%填白色rgba(255,255,255,0.8)、右侧60%填浅青rgba(100,200,255,0.6),两段颜色必须明显可分(不要单色白环,否则分段看不见)**,两段相加100%;中心白孔只写2-4字主题词,不写百分比数字
- 卡片4 右中:**流程卡片用编号①-⑦水平排列+极简图标,不在小玻璃卡片里写中文步骤标签(小卡里中文标签 garble 率高)**
- 卡片5 左下:单条折线,不画坐标轴,最高点/最低点旁标 callout 文字
- 卡片6 底中横条(y:80%以下,不侵入中央40%×50%保护区):4张小图缩略图横排,**缩略图下方不加中文标签**(避免 garble)

[顶部时间轴] 横贯画面宽度90%白色细线,恰好N个白色圆点节点,逐字列出①YEAR1 NAME1 / ②YEAR2 NAME2...;恰好N个不重复。

[全局] 卡片内中文标签必须是固定已知名词(如\"车体/转向架\"),不要开放式枚举短语(开放式\"四大XX\"类清单garble率~20%);禁止同字重复、禁止造字、禁止近形字替换;无水印无乱码;2K 16:9。底层照片像素级保留,绝不重绘主体、绝不改变建筑形状。"
```

两步法关键经验：
- **Donut 必须显式指定两段颜色**——"严格 2 段"还不够，必须写"左 40% 白 / 右 60% 浅青"两色对比，否则渲染成单色白环、分段不可见。
- **Workflow 卡片在小玻璃卡里不要写中文步骤标签**——中文标签在小 glass card 里会变成伪汉字圆圈。改用 ①-⑦ 编号圆圈 + 图标，步骤文字后期 HTML 叠加。
- **Bar 关键数值 anchor**：对最重要的 1-2 根柱子写"X 柱顶标 V，不是 W"防数值漂移；关键柱可 drift 数百；anchor 后明显稳定。
- **底卡 y 位置 ≤80%**：底中横条顶部要在 y=80% 以下（16-17% 高），不要侵入中央 hero 保护区。
- **开放式中文枚举短语 garble 率 ~20%**：改成固定已知名词（"车体/转向架/牵引/制动"）能显著降低。
- **代价**：多一次 API call（+¥0.30-0.60）；donut/workflow 卡片在第一步就弱，可能需要局部重绘或 HTML 叠加。
- **推荐场景**：hero 主体是人造物（建筑/列车/工业设备）且照片真实感要求高时用两步法；自然/野生动物一步法（Recipe 1-3）已达 9/10 不必多花一次。

## 翻车提醒（以下场景 AI 稳定失败，写在 brief 里提前告知用户）

1. **坐标轴刻度与小字标签**：X 轴月份/日期 100% 乱码（J 3 A A 5 G J 9 10 N 11 12 D / 1月 2月 5j 19 这类）——防御：`禁止J/F/M英文月份、禁止纯数字月份、禁止拉丁字母坐标轴`，最稳是**根本不画坐标轴**，柱顶直接标数值、折线只标两个 callout。即使加了防御仍有约 15% 失败率，一次跑 2-4 张挑。
2. **长段中文导语 / 多行副标题**：2+ 行中文 deck 必 garble（常见输出整段伪汉字乱码）——只保留一行英文副标题，**不写任何中文导语段落**。
3. **缩略图/设备下方中文 sub-label**：90% 乱码或截断——最稳做法是**单图不加标签**，只在卡片顶部加一行 4-6 字总标题。必须标签时每张 ≤4 字中文字。
4. **特定真实建筑/地点的像素级还原**：纯文字描述下模型稳定偏向科幻"钻石/切面"建筑，即使提示词很具体也只能得到"相似风格非精确复刻"。要精确还原要么接受"类似风格"，要么 img2img 用实拍图——但 img2img 会覆盖建筑身份，不是"保留一切加 overlay"。
5. **甜甜圈超过 2 段**：必自发长出灰色"其他"切片——必须写"严格2段、不要第三段、不要小切片、两段相加精确100%"，成功率约 80%。
6. **折线图形状不指定就乱**：不写形状约束模型会出双峰或塌成 24 小时曲线——特殊主题（极昼/季风/单峰趋势）必须显式写"单谷 V 形，波谷在 X 月，波峰在 X 月"。
7. **步骤流程编号必跳号/重复**：N 步经常出 N-1 或 N+1 步、编号重复/跳过——必须逐字枚举 `①X ②Y ③Z ④… ⑦…` 并加"编号连续不跳不重——禁止重复④、禁止跳过⑤⑥、禁止 N-1 步、禁止 N+1 步"；或直接退化为无编号图标列表（最稳）。
8. **柱图数值单位/数量级必错**：558 会变成 5584/5580/258/558米，y 轴 0-60 刻度映射到几千的柱值——必须显式写相对排序 + "数字是 X 不是 X0/X4/X*10"防御；最稳是不画 y 轴、柱顶直接写数值。
9. **时间轴/步骤图标会变随机 emoji 或涂鸦**——要么接受抽象彩色圆点做节点标记，要么步骤图完全不要图标只用编号圆圈+文字。
10. **Y 轴单位混乱**：米/平方米/百米/h/小时 经常互换，y 轴刻度 0-60 映射到数值几千的柱——防御是**不画 y 轴**，柱顶/数据点直接标"数值+中文单位"。
11. **竖版（3:4）文字 garble 约 2× 于横版**——竖版卡片 ≤5、不做图表、不做时间轴、文字全部"短标题+大数字+一行小字"三段式。
12. **甜甜圈中心文字 + 外侧引线标签同时存在**经常丢一个（模型常只渲染中心文字而不画 donut 本体）——显式写"中心白孔只写「X」2-4 个汉字（不写百分比）……两段外侧直接白色引线标注"，仍预期 1/5 失败率。
13. **Img2img 无法同时保留 hero photo 身份又加 overlay**——照片可保留但建筑身份易被覆盖、图表易退化；img2img 是单步编辑工具，不是万能合成器，默认走 text-to-image 路径（t2i 已能达到很高照片真实感，不需要参考图）。
14. **超过 6 张卡片**：6 张时 canvas 密度已经到顶，更多张必然压缩字号+文字 garble+卡片重叠；7+ 未经验证，不要尝试。
15. **英文月份缩写 / 拉丁字母坐标轴**：哪怕只是 "Jan/Feb" 也会被模型复制错乱成 "J 3 A A 5 G"——全局禁用，所有轴标签/月份/缩写一律中文。
16. **Donut center % 幻觉 + 分段颜色不可见**：只写"甜甜圈 40%/60%"会渲染成单色白环（分段看不见）；必须显式写两段颜色（"左40% 白色、右60% 浅青"），且中心不写百分比数字（中心只放 2-4 字主题词，百分比放外侧引线标注）。单色环导致分段不可见是已验证的失败模式。
17. **Bar 数值 drift（关键柱需 anchor）**：不做 anchor 的关键柱会 drift 几百——对 1-2 个最重要柱显式写"{{NAME}}柱顶标{{V}},不是{{WRONG_V}}"。
18. **小 glass card 内中文标签 garble**：右中 workflow / "X大核心技术"这类开放式中文枚举清单在小玻璃卡内 garble 率 ~20%。解决：(a) 改写成固定已知名词（"车体/转向架/牵引/制动"），或 (b) 只放编号圆圈+图标，中文文字后期 HTML 叠加。
19. **Card 区域侵入中央保护区**：底中横条顶部 y 必须 ≤80%（高度 16-17%），否则会覆盖 hero 主体下缘。
20. **照片真实感 vs 主体身份保留的 tradeoff**：纯 t2i（Recipe 1-3）出 9/10 照片感但建筑会漂成科幻 CGI；img2img（Recipe 4）照片真实感更强但图表/文字略弱、需多一次 API call。建筑/工业主体优先 Recipe 4，自然/野生动物优先 Recipe 1-3。
