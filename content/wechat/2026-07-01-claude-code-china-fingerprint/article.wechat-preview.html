Claude 封号潮：Anthropic 在你的系统提示词里写了隐形墨水

6 月 30 日，Reddit 上一条技术帖炸穿了中文和英文开发者社区：有人在 Claude Code 的二进制文件里，挖出了一段自 2026 年 4 月 2 日（v2.1.91）起就埋藏的检测代码。它不看 IP，不弹窗，不请求权限，而是悄悄读取你的系统时区和代理配置，然后把结论“纹”进每一句发给 Anthropic 的系统提示词里。

两天之内，国内社交媒体上涌出大量封号反馈：有人稳定用了一年的 Pro 账号突然阵亡，有 110 人规模的公司几乎被“团灭”，有人刚续费的 Max 订阅还没捂热就收到冻结邮件。而 Anthropic 的 Claude Code 负责人 Thariq 在 X 上回应：这是 3 月启动的一项“实验”，目的是防止未授权转售和模型蒸馏，相关代码会在下一个版本移除。

“实验”二字很轻，但它在终端里做的事情很重。如果爆料属实，这意味着一个被开发者赋予文件系统、Shell 和代码仓库读写权限的 AI 代理，在长达三个月的时间里，用一种连安全扫描都难以发现的隐蔽信道，向服务器传递用户的地理与组织属性。今天的标签是“中国用户”，明天的标签可以是任何东西。

一、它不是地理封锁，而是“终端纹身”

长期以来，大家默认 Claude 对中国用户的限制就是 IP 地理封锁：开代理、绑海外卡、接第三方 API，绕过去就行。但这次被挖出的机制完全不同——它根本不看网络出口 IP，而是直接读你的电脑本身。

触发条件大致如下：

  1. 你修改了 ANTHROPIC_BASE_URL，把 Claude Code 指向非官方的代理或中转站；
  2. 代码读取系统时区，看是不是 Asia/Shanghai 或 Asia/Urumqi；
  3. 代码解析代理 URL 的主机名，比对一份内置的域名与关键词列表，判断你是否连到了中国域名、中国 AI 实验室，或两者兼有。

这一步本身已经够敏感：一个编程助手在未经明确告知的情况下，扫描本地环境并向云端回传结论。但真正让人起鸡皮疙瘩的是第二步——它不是明文上报，而是把结果编码进系统提示词。

二、系统提示词里的 Unicode 隐写术

Claude Code 每次发请求前，都会在系统提示词里拼上一句很普通的话：Today's date is 2026-06-30.

这句话的唯一作用，本来只是让模型知道今天是几号。但据逆向工程披露，当检测到“中国属性”时，Claude Code 会对这句话做两处肉眼几乎无法分辨的修改：

第一处：日期分隔符。

  • 正常格式：2026-06-30（连字符）
  • 中国时区：2026/06/30（斜杠）

第二处：Today’s 里的撇号。

根据代理域名的匹配结果，普通的 ASCII 单引号 '（U+0027）会被替换成三个外观高度相似、但 Unicode 编码完全不同的字符之一：

放到实际的 system prompt 里，大概就是下面这样。注意：肉眼看这五句几乎一模一样，但后端解析时，日期分隔符和撇号的 Unicode 编码已经暴露了环境属性。

text
// 正常环境：非中国时区、非中国代理
Today's date is 2026-06-30.

// 中国时区（Asia/Shanghai 或 Asia/Urumqi）
Today's date is 2026/06/30.

// 中国时区 + 中国域名，但非 AI 实验室
Today’s date is 2026/06/30. // 撇号为 U+2019

// 中国时区 + 中国 AI 实验室，但非中国域名
Todayʼs date is 2026/06/30. // 撇号为 U+02BC

// 中国时区 + 中国域名 + 中国 AI 实验室
Todayʹs date is 2026/06/30. // 撇号为 U+02B9

Anthropic 后端收到请求后，只需要解析提示词里那一个小小的日期格式和撇号编码，就能判断这条请求是否来自中国、来自普通用户还是来自被盯上的 AI 实验室。整个过程不需要额外 HTTP 字段，不触发常规流量审计，也不会在界面上留下任何痕迹。

在信息安全领域，这种把信息藏进看起来完全正常的文本载体的做法，有一个专门的名字：隐写术（Steganography）。

三、更隐蔽的是代码本身

如果这段逻辑明晃晃地写在源码里，或许早就被社区发现。但爆料者称，Anthropic 对它做了多层伪装：

  • 压缩混淆：原本应该叫 checkTimeZone() 或 isChineseProxy() 的函数，被替换为 Crt()、Rrt(e)、e0t()、Zup() 这类无意义短名，不同版本还会变化；
  • XOR 加密 + Base64：内置的域名列表和关键词不是明文，而是用密钥 91 做异或运算后再 Base64 编码，普通 strings 命令根本扫不出来；
  • 只在代理模式下激活：直连 Anthropic 官方 API 的用户不会触发这段逻辑，恰好降低了被大规模逆向撞见的概率。

从技术对抗的角度看，这不像是一个“临时实验”该有的防护等级。它更像一个被认真设计、希望长期潜伏的检测通道。

四、为什么这比封号更可怕

如果你只是把 Claude 当作网页聊天工具，这件事的严重性或许还停留在“隐私侵犯”层面。但 Claude Code 不是网页聊天工具。它是一个安装在你本地终端、默认就能读取项目文件、编辑代码、运行 Shell 命令的 AI 代理。

你让它看过你的 .env 文件吗？让它执行过 git push 吗？让它帮你生成过 Dockerfile、CI 配置或密钥管理脚本吗？如果一段客户端代码可以在你毫无察觉的情况下修改系统提示词，那它理论上也可以做很多事——而且你很难知道。

这正是社区反应如此激烈的原因：

  • 信任边界被击穿：用户把 Claude Code 当作“自己的工具”，但它被设计成可以向服务器偷偷发送本地环境信号；
  • 先例一旦打开就收不住：今天是时区和代理域名，明天可以是操作系统语言、键盘布局、进程列表、相邻 Wi-Fi、剪贴板内容；
  • 误伤面极大：真正的模型蒸馏团队完全有能力修改时区、换域名、打补丁绕过检测，最终被精准锁定的往往是普通开发者。

Anthropic 说自己是在防御“未授权转售”和“模型蒸馏”。但防御方的合法性，不能自动为任何手段背书。尤其是在一个被赋予了本地高权限的工具里，隐蔽信号传递的伦理边界，远高于一次普通的反爬风控。

五、Anthropic 的回应与未回答的问题

7 月 1 日，Claude Code 负责人 Thariq 在 X 上回复：

“这是我们 3 月启动的一项实验，旨在防止未授权转售商滥用账号并防御模型蒸馏。团队已经落地了更强的缓解措施，我们也一直计划下线该功能，相关移除 PR 已合并，会在明天发布的版本中完全回滚。”

这番回应承认了机制存在，但留下了更多问题：

  • 如果“只是实验”，为什么从 4 月 2 日上线到 7 月 1 日被曝光，期间没有任何公开说明或更新日志？
  • 在这三个月里，有多少中国用户的提示词被悄悄打上了标签？这些标签是否进入了风控决策、封号决策或模型训练数据？
  • “更强的缓解措施”是什么？是否同样不透明？
  • 如果不是被逆向工程曝光，Anthropic 打算什么时候“计划下线”？

更值得玩味的是时间背景。就在同一周，Anthropic 刚向美国参议院指控阿里巴巴通过近 2.5 万个虚假账号、总计 2880 万次交互，对 Claude 发起“史上最大规模蒸馏攻击”；同时美国政府刚解除对 Claude Fable 5 和 Mythos 5 的出口管制。地缘政治、商业竞争和模型安全三条线，在这一刻交汇到了 Claude Code 的二进制文件里。

六、作为普通开发者，能做什么

在 Anthropic 正式移除这段代码之前，如果你担心被误伤，可以考虑以下做法——但请理解，这并不能解决根本问题：

  1. 尽量使用官方 API 端点，避免通过来路不明的中转站调用 Claude；
  2. 将系统时区改为非中国时区，例如 UTC 或你代理服务器所在地时区；
  3. 在隔离环境中运行 Claude Code，比如 Docker 容器或虚拟机，限制其对本地文件和配置的访问；
  4. 不要把高度敏感的项目直接交给任何云端 AI 代理处理——这不是针对 Anthropic，而是所有具备本地执行权限的闭源工具都应遵守的安全基线。

最根本的解药，其实是行业层面的透明与审计。当 AI 代理越来越深地嵌入开发者的计算机时，用户有权知道：什么数据被读取、什么信号被发送、什么决策被做了。任何以“安全”或“反滥用”为名的隐蔽机制，都必须接受独立安全审计和公开披露。否则，“防止滥用”和“滥用监控”之间的界限，只会越来越模糊。

结语：当 AI 代理学会写隐形墨水

这件事最终会怎么收场？Anthropic 大概会如约移除这段代码，发一篇措辞谨慎的公告，然后舆论慢慢平息。但它留下的阴影不会这么快散去。

我们正处在一个微妙的转折点：AI 不再只是回答问题的聊天机器人，而是开始替你操作文件、执行命令、管理仓库。当这样的工具被发现在你的系统提示词里写隐形墨水时，真正值得追问的不是“Anthropic 有没有做错”，而是——我们是否已经准备好，把这么高的信任和权限，交给一个会对自己保密的软件？

下一次，当你对 Claude Code 说“帮我看看这个 repo”的时候，不妨多想一层：它看到的，会不会比它告诉你的更多？
