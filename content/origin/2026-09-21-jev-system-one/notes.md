## 方法与坑点（可复用）

1. **两条臂必须喂同样长的文档。** 第一轮我给 Jev 1200 字符、给 Qwen 2000 字符，
   Jev 的 token 消耗看着更少——那是"谁看的多"的差别，不是判断力的差别。已修成同一常量。
2. **两条臂必须同并发度。** 第一轮 Qwen 串行、Jev 并发 8，墙钟差 8 倍里有一部分是并发度造成的。
3. **BM25 必须补齐到 K。** 只返回命中项会让短查询（NFCorpus 的 "bagels"）拿到空候选集，
   那测的就不是重排而是检索了。真实 BM25 对全部文档排序，不命中的得 0 分但仍在候选里。
4. **中文的 token 密度是英文的 3 倍以上。** 50 篇文档时中文每篇只能放 600 字符
   （800 字符 ≈ 27.9K token 就会被 `max_tokens_exceeded` 拒掉，1500 字符必拒）。
   Jev 的 32K 是 "state + 最长问题" 共享的，比 Qwen 那个纯 32K 更紧。
5. **纯 Python 倒排索引撑不住 11.8 万中文文档**（12 分钟没建完、3.4GB）。
   换 `bm25s`（scipy 稀疏矩阵）后分词 19.5s + 建索引几十秒。脚本：`build_zh_shortlist.py`。
6. **HF 下载走 hf-mirror.com 快一倍**（4 MB/s vs 1.75 MB/s），且断点续传可靠。
