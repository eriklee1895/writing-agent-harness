# seed-audio-1.0 官方实践手册对照与多参考/延长能力补测（2026-08-27）

## 背景

Erik 提供字节内部《豆包音频生成模型1.0 实践手册》（飞书 wiki，2026-06 发布），要求对照 seed-audio-gen skill 找可借鉴点。手册是 UI 体验中心向的使用指南，但暴露了几个我们 skill 未覆盖或未实测的能力。

## 实验验证（2026-08-27，真实 API 调用）

| 实验 | 结果 |
|---|---|
| 2 条参考音频 + `<<TGT_SPK1>>/<<TGT_SPK2>>` 绑定 | ✅ 成功，字幕干净无 token 泄漏（37s/24s） |
| 2 条参考音频 + `@音频1/@音频2`（UI 语法） | ✅ 同样成功 |

| 图片 + 音频参考混用 | ❌ API `45001001: image reference cannot be mixed with audio or video references`（报错信息还暴露 API 存在 video reference，未文档化） |
| `音频总时长：15秒` 声明 | ✅ 输出精确 15.0s |
| 顶层 `section_id` 字段 | 200 接受但效果不可验证（未知字段可能被静默忽略）→ 不采用 |

## 关键结论

1. **多参考音频绑定语法**：官方后台 prompt 用 `<<TGT_SPK1>>`（"饰演者为 <<TGT_SPK1>>"），UI 的 `@音频1` 是其前端编译形式。我们 prompt-guide 里写的 `@Audio1` 是此前未验证的类比写法，已更正为 `<<TGT_SPKN>>`。绑定方向（第 N 条参考对应第 N 个角色）需人耳确认，测试音频在 `/tmp/seedaudio-doc/exp/out/`（A_tgt_spk / B_at_yinpin 两个文件可对比）。
2. **音频延长 workflow**：官方文档明确「以此作为参考输入延长音频，可以在多次音频延长中保持音色的高度一致」——即把上一段输出回灌为 `--ref-audio`。不需要 section_id，现有 references 机制即可支撑，补文档即可。
3. **图片参考**：API 已支持（手册 UI 标注「敬请期待」但 API 先行），不能与音频参考混用，已做 CLI 前置校验。
4. **Prompt 工艺增量**（来自官方 6 个成片案例）：角色列表前置 + 风格标签（现代剧/古装剧/播客/译制片）、口音（台湾腔/东北腔/译制腔）、声音处理（电话失真/遥远）、群杂（群体喊声）、非语言词汇（气声/吞口水/磕巴/尖叫/哭腔）、跨角色重叠（"句首和笑声重叠"）、播客毛边感（附和声"对/嗯/是"、吞字、停顿）、配乐器声部具象化（弦乐组/跳音/pad 铺底）。
5. **20 语种清单**：手册给出完整列表，含中英日韩外的墨西哥西语、印尼语、马来语、德语、巴西葡语、法语、泰语、越南语、菲律宾语、意大利语、俄语、荷兰语、波兰语、土耳其语、瑞典语、西班牙语；台词用目标语言、音色描述可用另一语言。
6. **文本密度机制官方确认**：文本过长时模型会**加快语速**塞进时长——印证我们 400 字台词建议。
