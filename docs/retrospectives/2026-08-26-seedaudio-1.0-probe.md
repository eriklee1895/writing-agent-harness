# seed-audio-1.0 能力摸底与 seed-tts-2.0 对比

**日期**: 2026-08-26
**数据来源**: 官方文档 `docs.volcengine.com/docs/6561/2550782`（音频生成 HTTP）+ 本机账号实测 10 个用例
**账号**: Erik 本机火山账号（支持 seed-audio-1.0）

## seed-audio-1.0 是什么

火山引擎「豆包音频生成」大模型，**生成式音频**而非传统 TTS。一次调用（非流式）从自然语言 `text_prompt` 生成最长 120 秒音频，可包含**多人对话、音效、环境音、音乐**，支持参考音频克隆 / 参考图片 / 参考音色 ID。

- 端点: `POST https://openspeech.bytedance.com/api/v3/tts/create`
- 鉴权: 仅 `X-Api-Key`（**无** `X-Api-Resource-Id`，与 seed-tts-2.0 不同）
- 请求体: `{model, text_prompt, references[], audio_config, watermark}`
- 计费: 按 `original_duration`（秒），上限 120s
- 输出: base64 音频 + `duration` + `original_duration` + `url`（2h CDN）+ `subtitle`（可选）

## 实测结果（2026-08-26）

| 用例 | 内容 | 延迟(s) | 音频(s) | xRT | 大小KB | 备注 |
|------|------|---------|---------|-----|--------|------|
| A1 | 纯文本单旁白 | 19.5 | 9.3 | 0.5 | 147 | 无 ref，自带前导静音 |
| A2 | 纯音效（雷雨）| 26.3 | 7.5 | 0.3 | 119 | 无字幕（非语音）|
| A3 | 双人对话 | 14.8 | 6.9 | 0.5 | 109 | 描述音色生成 |
| A4 | 完整场景（人声+SFX+音乐）| 21.8 | 24.1 | 1.1 | 378 | 最长，能力天花板 |
| A5 | ref speaker ID | 17.6 | 4.2 | 0.2 | 67 | 复用 Vivi 音色 |
| A6 | 英语生成 | 16.3 | 3.8 | 0.2 | 60 | Dacey 音色 |
| A7 | 时间轴控制 | 17.4 | 5.8 | 0.3 | 92 | 3s静音+说话+2s静音，成立 |
| A8 | 字幕开启 | 27.4 | 8.8 | 0.3 | 139 | 返回句+词级时间戳 |
| B1 | seed-tts-2.0 纯文本 | 31.2 | 6.5 | 0.2 | 51 | 64kbps，首调用偏慢 |
| B2 | seed-tts-2.0 + context | 3.4 | 6.8 | 2.0 | 54 | 暖启动快 |

**音频保真度**: seed-audio 输出 **128 kbps** MP3，seed-tts-2.0 输出 **64 kbps** — 前者单位时长信息量 2 倍。

**字幕结构**: A8 实测返回 `subtitle.text`（整段）+ `sentences[]`（句级 start_ms/end_ms）+ 每句 `words[]`（词级 start_ms/end_ms）。例句首词 "在" 2800→3040ms，证实音频自带 ~2.8s 前导静音。

**边界**: text_prompt > 3000 字符 → HTTP 400, code `45001116`，"length N exceeds maximum of 3000"。干净报错。

## seed-audio-1.0 vs seed-tts-2.0

| 维度 | seed-audio-1.0 | seed-tts-2.0 |
|------|----------------|--------------|
| 范式 | 生成式音频（LLM 驱动 prompt）| 确定性文本转语音 |
| 输入 | 自然语言场景描述（≤3000 字符）| 待朗读文本（verbatim）|
| 输出 | 多人对话/音效/音乐/环境音，最长 120s | 单音色单段语音 |
| 传输 | 非流式（一次性返回）| HTTP chunked 流式 |
| 保真度 | 128 kbps | 64 kbps |
| 计费 | 按秒（original_duration）| 按字符（text_words）|
| 风险 | LLM 可能改写/增删内容 | 严格 verbatim |
| 参考 | 音色 ID / 音频克隆 / 图片 | 音色 ID / context_texts 情感指令 |
| 延迟 | 14-27s（与输出时长正相关）| 3-30s（首调用有冷启动）|
| 字幕 | 句+词级 ms 时间戳 | 字级时间戳（forced alignment）|

## 适用场景

**seed-audio-1.0 适合**:
- 有声书 / 广播剧（多角色 + 情绪 + 场景音）
- 影视配音 / 游戏音效（SFX + 配乐一次性生成）
- 视频片头/预告音频（人声 + 音乐 + 音效混合）
- 不要求 verbatim、允许 LLM 演绎的创意音频

**seed-tts-2.0 适合**（保持现状）:
- 视频旁白 / 技术解说（必须逐字准确）← 本 repo 主场景
- 批量长文本朗读（按字符计费、流式、低延迟）
- 需要精确字级时间戳做字幕对齐的场景
- 数学/教育朗读（LaTeX parser）

## skill 决策

**建议: 新建独立 skill `seedaudio-gen`，不要合并进 `volcengine-tts`。**

理由（对照 [[multi-tier-model-skill-dont-split]] 的反例判断）:
- 不是子集关系，是不同范式（生成式 vs TTS）。Seedream Pro/Lite 不拆是因为严格子集 + 代码共享；此处相反。
- API 形状完全不同: `/tts/create` vs `/tts/unidirectional`；body `{model,text_prompt,references}` vs `{req_params:{text,speaker}}`；鉴权头不同。
- 误用代价高: seed-audio 会改写文本，用于旁白会出事故；seed-tts-2.0 做不了 SFX。skill 边界必须分开。
- 共享项仅 API key 约定（`~/.volcengine.env`），可在两个 SKILL.md 互指。

skill 形态建议:
- `scripts/seedaudio-gen.py`（PEP 723，单句 + batch）
- `references/seedaudio-prompt-guide.md`（场景语法、时间轴控制、@音频N、音色选择）
- `SKILL.md`（与 volcengine-tts 互指 "When NOT to use"）

## 补充调研（web search workflow，6 agent / 80 万 token）

官方定位：「业内首个可通过单条 Prompt 直接生成影视级音频的模型」。
- **发布**: 2026-06-23（火山方舟邀测），体验中心送 30 分钟免费额度，计划接入剪映/即梦/番茄
- **无流式变体**: 官方 curl 用 `--max-time 300`（5 分钟），证实是批量/生产操作，非实时
- **一声多角**: voice/style 解耦，单音色可饰多角色
- **长片段音色一致性**: 有 extension 功能跨段保音色；长内容建议把满意的参考音频训练成固定 Speaker ID
- **语种争议**: model-list 文档(2499930)只写「中文+英文」；HTTP API 文档(2550782)列 18 语种。实测 A6 英语成立。保守按「至少中英确认，其余 16 语种用前先测」
- **定价未公开**: 仅知按 `original_duration` 秒计费、上限 120s；具体单价需查控制台或计费 FAQ
- **第三方印证**: qwen3tts.com 明确「不是 TTS endpoint，更适合生产 workflow 而非实时 agent」

## 第二/三轮补充测试（视频配音/公式/BGM/克隆/SSML/语速/情感）

- **视频配音 verbatim 可控**：C4 实测，seed-audio 加「请逐字朗读，不要增删改」指令后，字幕文本与输入完全一致。但非流式 27.8s 延迟 + 120s 上限 + verbatim 靠 prompt 非 API 保证
- **公式朗读反超**：C2 实测 `$a^2+b^2=c^2$` + `$\sqrt{3^2+4^2}$`，seed-audio LLM 自然读对；seed-tts-2.0 `--latex --latex-parser v2` **解析失败**（0 音频）
- **能生成纯 BGM**：C3 生成 20s 纯音乐（314KB），但非专用音乐模型，质量 vs BigMusic 待人工对比
- **音色克隆成立**：C1 用 seed-tts-2.0 悬疑解说 5.2s 参考音频作 audio_data，seed-audio 生成 3 段不同文本，全部成功（延迟 20-33s）
- **SSML/拼音是 seed-tts-2.0 独占**：seed-audio 无 ssml 字段，多音字靠自然语言括号注音（可行但不如 SSML 精确）
- **情感控制两者都支持**：seed-audio 用 prompt（丰富但慢 17s），seed-tts-2.0 用 context_texts（受限但快 1.3s）
- **预置音色**：seed-audio 无独立音色列表，复用 seed-tts-2.0 全部 115 个 `_bigtts` 音色 + 复刻音色

## 费用对比

- seed-audio-1.0：后付费 1 元/分钟（按秒），资源包最低 0.8 元/分钟
- seed-tts-2.0：后付费 3 元/万字符（按字符），资源包最低 2.1 元/万字符
- 等价换算（中文旁白约 240 字/分钟）：seed-tts-2.0 约 0.072 元/分钟，**纯旁白成本便宜约 14 倍**

## volcengine-tts CLI additions bug（已修复）

排查 seed-tts-2.0 公式朗读「6/6 全失败」时发现 CLI bug：`volcengine-tts.py` 把 `additions` 字段传成 JSON object，但 API 期望 JSON string，触发 `cannot unmarshal object into Go struct field TTSReqParams.req_params.additions of type string` 反序列化错误（code 55000000）。

影响范围：所有走 `additions` 的参数——`--latex`、`--latex-parser`、`--pitch`、`--watermark`、`--strip-markdown`、`--strip-emoji`、`--silence-duration` 全部静默失败（API 不报错但返回 0 音频）。

修复：`body["req_params"]["additions"] = json.dumps(additions)`（第 220 行）。

修复后 seed-tts-2.0 LaTeX v2 parser 6/6 全过，与 [[tts-education-latex-parser-default]] memory 一致——之前那条 memory 是对的，是 CLI bug 导致本轮测试假性失败。

**教训**：测试中发现的「模型能力失败」先疑 CLI/API 调用链，再下模型结论。对照 [[api-claim-must-verify-with-code-grep]] 和 [[skill-edits-verify-documented-examples]]——别凭表面失败反推模型能力。

## 带音效的配音（G 系列，第四轮补测）

3 个递进场景（G1 单音效 / G2 环境音 / G3 多层音效），同文案两模型对照：
- **seed-audio 音频更长**：G3 13.1s vs seed-tts 7.9s，多出的 5s 是雷雨音效层
- **字幕确认 verbatim**：音效不影响人声准确性
- **延迟代价大**：seed-audio 25-65s vs seed-tts 2-4s，慢 10-25 倍——LLM 生成多元素成品的结构性代价
- **seed-tts 做不了音效**：同样效果需 TTS 出人声+音效库找素材+后期混音，工作流长得多

结论：需要「人声+音效」成品的配音（影视/游戏/有声书）用 seed-audio 一步到位；纯旁白用 seed-tts 后期混音更快更便宜。

## 生成速度对比（按场景拆分）

### TTS 场景（生成人声旁白）
- seed-tts-2.0: 3.16s→16.87s, xRT 5.33（流式，快 11 倍）
- seed-audio: 19.5s→9.3s, xRT 0.48（非流式，最慢）

### BGM 场景（生成纯音乐）
- BigMusic: 25.34s→30s, xRT 1.18（时长精确可控，专用音乐模型）
- seed-audio: 17.66s→20s, xRT 1.13（时长 LLM 粗控，附带能力）

结论：纯人声旁白用 seed-tts-2.0（快 11 倍）；精确时长 BGM 用 BigMusic；多元素混合成品用 seed-audio（最慢但省后期混音）。

## seed-audio 适合的场景

1. 有声书/广播剧（多角色+情绪+场景音一次出）
2. 影视配音/游戏音效（人声+音效混合成品）
3. 视频片头/预告音频（人声+音乐+音效短成品）
4. 音色克隆+多段生成（0 样本，≤30s 参考音频）
5. 需要情感/角色/时间轴精细控制（prompt 驱动比 SSML 丰富）
6. 复杂数学公式朗读（C2 实测比 seed-tts-2.0 LaTeX parser 稳）

不适合：批量长文本旁白（慢+贵）、verbatim 逐字精确（prompt 非保证）、精确时长 BGM、实时对话、SSML 精确控制。

**一句话定位**：seed-audio 是「成品音频创作模型」，不是更快的 TTS 也不是更好的 BGM 生成器。价值在于把 TTS+BGM+音效+后期混音的多步流程压成一次调用。
